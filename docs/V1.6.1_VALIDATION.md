# MyAI V1.6.1 交付与验证记录

基线：2026-10-08 上一轮完整 MyAI_V1.6.zip；在本次工作目录解包后增量修改，没有退回 V1.5.1。未上传 GitHub。

实际修改：ai.py（自动记忆保守筛查，复用原整理请求）、memory.py（事务内兼容迁移、有效记忆读取、candidate 更新保护、新偏好分类）、gui.py（仅版本标题）、README.md、CHANGELOG.md。
新增：foundation_time.py、proactive_timeline.py、memory_retention.py、affect_state.py、tests/foundations_test.py、本验证记录。
逐字节保留：time_context.py、context.py、所有 llm/*.py Provider/Vision、settings.py、media.py、emotion.py、relationship.py、requirements.txt、原全部测试及离线隔离入口。旧 AUDIT.md/V1.6_VALIDATION.md 为历史记录。

DB migration：原 init_database 事务内 CREATE TABLE IF NOT EXISTS pending_actions，包含所有要求字段和 payload/last_reviewed_at/review_count，新增 status 索引；memories 按 PRAGMA 检查，仅 ADD COLUMN retention_category、confidence、expires_at、retention_status、metadata。旧内容、原主题 category、ID 和既有时间戳不改写，旧记录保持 active。幂等迁移测试通过。新增记录和队列使用 V1.6 clock abstraction；旧基础数据库接口保留原时间行为。

队列：create/schedule、get、get/list due、defer/cancel/expire/completed、review/reconsider；eligible 不改变为 completed、不执行消息、不调用 Provider。review hook 接收 ReviewContext，调用后再次检查过期/状态；异常不授权执行。没有 sender、后台线程/定时器、弹窗或屏幕读取。V1.7 必须在实际执行前再次审核最新上下文，本版不保存可复用发送许可。

记忆：typed retention API 支持五类；临时记录强制 TTL/expiry，性格推断即使 confidence=1 仍 candidate，敏感推断不落盘。候选/过期记录不进入 load_memories 和 prompt。自动整理使用原一次请求，加 prompt 约束与保守关键词规则；未实现完整语义分类，未标注/未命中规则的推断仍可能漏判，属于后续审核方向。临时自动信息默认 24 小时 TTL。candidate 不显示已记住，不覆盖已有明确事实。旧手动写入按用户明确事实保存。

Affect：独立可选内存状态，范围校验、线性衰减和过期/损坏时间 neutral；没有接入回复流程或永久档案，emotion.py 原样保留。默认 30 分钟 TTL，不额外调用模型或采集摄像头。

时钟：FoundationClock 复用 TimeContextService.clock（支持 fake clock），进程内高水位防止时间倒退导致状态复活。无网络校时；跨重启不持久化高水位。损坏时钟拒绝基础设施操作；坏队列时间 fail closed 为 expired，坏记忆 expiry 排除，坏 affect 时间 neutral。

最终验证：Python 3.14；python -m compileall -q . 退出码 0。
全部原有八组 smoke/offline 脚本通过（40 unittest + smoke）；V1.6 temporal_test 6 项通过；新增 foundations_test 10 项通过。合计 56 unittest + smoke。
